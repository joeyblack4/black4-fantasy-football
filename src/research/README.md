# Bounded franchise research tools

`createOwnerResearchTools(db, options?)` returns the `OwnerReadTool[]` interface used by `OpenRouterDriver`:

- `research_sources`: list trusted public sources and availability.
- `research_retrieve`: retrieve one permitted URL, return a bounded untrusted excerpt, source links, provenance and receipt.
- `research_search`: direct Firecrawl search when configured; otherwise explicitly unavailable. No invented search results.

Initial sources are NFL's [news](https://www.nfl.com/news), [injury reports](https://www.nfl.com/injuries/) and [schedule](https://www.nfl.com/schedules). Public pages and the actual pinned-IP reader were checked on September 7, 2026. All three returned HTTP 200. This establishes public reading capability, not a licensed live statistics feed, search account, or paid subscription entitlement.

Operator opt-in `createOwnerResearchTools(db, {retrievalMode: 'general-public'})` permits public HTTPS articles beyond that starting catalog. The default remains `catalog-only`. Public mode uses the same DNS-address pinning and bounded reader, rejects IP literals/internal hostnames, credentials, nonstandard ports, query strings and redirects, and supplies only untrusted excerpts with source-time uncertainty. Login, cookies, JavaScript rendering, subscription access and guaranteed availability of X/Reddit/FantasyPros are not provided. Returned links pass the same URL policy; resolved addresses are checked again when fetched.

Direct Firecrawl is the selected paid search backend. Construct `FirecrawlClient({apiKey, enabled})` and `FirecrawlResearch(db, {client, enabled, budget})`, then pass `{firecrawl, retrievalMode: 'general-public'}` to the shared tool factory. All owners receive the same tools. `research_search` calls [Firecrawl v2 search](https://docs.firecrawl.dev/api-reference/endpoint/search) for three plain descriptions. `research_retrieve` defaults to the unauthenticated public HTTPS reader with no paid API charge; `reader: 'public'` also selects it explicitly. Only `reader: 'firecrawl'` selects paid [v2 scrape](https://docs.firecrawl.dev/api-reference/endpoint/scrape), with markdown only, basic proxy and PDF parsing disabled. Scrape may omit credit usage, leaving its full reservation held even when content succeeds. No `/agent`, `/extract`, JSON extraction, model summary, or alternate reasoning model is requested. There is no automatic fallback or paid retry.

The existing `serverSearchAvailable` option is retained for compatibility but must be false/omitted when Firecrawl is configured. The two paid backend declarations cannot be enabled together. OpenRouter server-search is not used by this direct adapter.

Paid operations have durable league/owner/job/fence/request/response attribution in migration033. An agent row lock serializes wallet checks; stage accounting includes independent research holds alongside model reservations. Repeated operation keys return the original result or hold, and changed payloads conflict. Crashes, network errors, absent credits and excessive reported credits keep the entire configured reservation and block further paid reads. No hold is silently released. A request reporting credits may settle their approved internal allocation even if the request failed; a failed request does not imply zero cost.

The approved initial configuration allocates 3800 micros per reported credit, reserves 5000 micros per credit with a five-credit cap per operation, and limits each franchise to 100 credits. Thus each request reserves $0.025. These are internal plan allocations based on the observed $19/5000-credit plan, not observed marginal cash charges. Missing credit usage remains unknown. Credit and dollar limits are enforced separately. The approved tariff timestamp and receipt are required before dispatch; no key/account setup automatically enables paid reads.

Search documents top-level `creditsUsed`; scrape's current public reference does not promise that field. The adapter accepts observed numeric `creditsUsed` or `data.metadata.creditsUsed` and records which field supplied it; otherwise it holds for reconciliation. [Team activity](https://docs.firecrawl.dev/api-reference/endpoint/activity) can identify provider jobs, but its documented activity rows do not establish their credit charges. Do not infer per-franchise usage from a shared account balance delta while unrelated requests may occur. No automatic activity-based settlement is implemented.

Firecrawl target URLs are checked for public HTTPS syntax and public DNS before submission, but the remote provider controls its own fetch and redirects. This is not local socket pinning of the remote fetch. The unauthenticated public reader retains local DNS pinning. Target credentials, private hosts, custom headers and unsafe options cannot be supplied through the owner tool schemas.

The trusted application supplies the source allowlist. Models cannot add hosts, change allowed paths, supply headers or credentials, select ports, or follow redirects. HTTPS requests resolve DNS, reject nonpublic addresses, pin the validated address to the TLS socket, and preserve the original hostname for certificate validation. The reader sends no provider/account headers, ignores proxies, rejects compressed responses, and bounds DNS/request time and the body to four megabytes. NFL news/schedule HTML exceeded the original one-megabyte bound; the tested four-megabyte ceiling accommodates their current approximately 1.6–1.8 MB pages without removing bounds.

Only a current, enabled, league-bound, fenced runtime job can use these tools. There are at most eight retrieval/search receipts per job and sixty per owner per hour. Public reads have no API purchase path. Paid Firecrawl additionally requires the explicitly approved credit tariff and budget configuration described above; tool inputs cannot expand it.

Cache entries retain a bounded plain-text excerpt, at most five short allowed links, title, content hash and source-time metadata. Raw HTML is discarded. Excerpts are capped at 120 words; script/style/navigation content is removed, and no HTML is executed. All returned source content is explicitly untrusted and cannot authorize instructions or spending.

A declared article timestamp is separate from retrieval time. Missing source time stays unknown; an old article fetched moments ago is not described as fresh news. Future/invalid source timestamps are rejected as unknown. Shared short-lived cache leases prevent duplicate concurrent page fetches. Completed retrievals and failures have durable league/owner/job receipts; failures never substitute invented football information.

`npx vitest run tests/research.test.ts` verifies URL and address boundaries, redirects, body limits, error redaction, source-time uncertainty, bounded extraction, cache reuse, concurrent fetch leases, fenced job authority, request limits, and explicit unavailable search. Unit/integration fixtures are synthetic; separate read-only public network checks established that the initial official pages are reachable.
