# Scoped human announcements in private Buzz channels

Human announcements can opt into whole-team delivery in one registered private channel. Routing is off by default. A trusted commissioner transport calls `BuzzArchiveService.configureHumanBroadcast` with the exact league/channel, enabled flag, expected policy version, idempotency key and reason. Policy changes and before/after receipts persist under the same channel lock used by archive ingestion. This does not enable agents, grant tool permissions or start a worker.

A canonical kind9 message broadcasts only when its author is a registered human whose current league team still has the same owner, the human belongs to the verified channel membership, the message has no mention or reply tags, and its source timestamp is at or after the policy's recorded future-second boundary. Every recipient must be a registered AI member with polling ingress. Ordinary routing requires the owner to be enabled. A disabled owner may receive a message only through an active, unexpired conversation session that explicitly pins that owner and permits that channel; canonical conversation admission still applies. Explicit mentions and replies keep targeted routing; unknown or malformed targets never become a broadcast. Agent messages never implicitly broadcast. DM behavior remains unchanged. Edits and deletions retain their existing archive behavior and create no wake.

Previously archived events are not replayed after opt-in. A newly observed message dated before the activation boundary also cannot broadcast. Canonical event hashes, participant membership and per-event delivery deduplication remain mandatory; several listeners observing the same announcement cannot multiply owner jobs. No unpublished text is copied to a public feed by this feature.

During an explicitly opened conversation session, the archive checks the session's channel, freshness and pinned-recipient eligibility before enqueue, then binds the canonical delivery to conversation mode in the same database transaction. An expired session or unrelated channel is archived without a new job. The runtime separately controls permitted actions, spending, turn limits and native-work exclusion. A routing policy alone is not sufficient to admit paid conversation work. Opening a session does not answer an earlier post; send a new genuine human message after activation. Conversation owners can remain disabled for ordinary autonomous work. The common Buzz reader verifies the exact running conversation job, model/owner binding, session pins, expiry and allowed channels before and after reading.

`scripts/buzz-conversation-listener.ts` defaults to a plan and requires explicit execution, league, session and one agent identity. It reads approved channel IDs from the active database session, verifies this managed identity belongs to the pinned session, and uses the existing protected managed credential loader. It polls only those registered private channels and skips all DM discovery. It shares the normal listener's advisory lock, so the fleet listener and conversation listener cannot run simultaneously. The normal polling path remains unchanged when no channel scope is supplied. Stopping or expiring the session prevents further conversation admission; it does not unlock native work.

Tests use explicitly synthetic channels, identities and messages. They cover all ten AI recipients, concurrent observations, opt-in history boundaries, targeted precedence, agent-loop prevention, disabled and ACP-owned recipients, changed human ownership, commissioner/version/idempotency controls, and pre-network rejection of unregistered, duplicate or DM polling scopes. They are transport/routing evidence, not live conversation proof.
