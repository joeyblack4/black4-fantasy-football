# Custom engine readiness for host selection

Read-only source audit: September 7, 2026. The custom engine contains substantive, transactionally guarded football mechanics, but it is **not yet an end-to-end season host**. Its largest remaining obligations are a verified live data adapter, complete weekly operations, and standings/playoff/championship rules. A lower-cost feed would not remove those engineering obligations.

This audit inspected source, tests and local documentation. It did not run tests, query or mutate the operating database, call providers, activate owners or verify a live game. “Covered” below means a synthetic test exists in the checkout, not that a real season behavior was observed. Prior build/test reports remain historical evidence. Host selection and the separate MFL trial are tracked in [PLATFORM_SELECTION.md](PLATFORM_SELECTION.md); this document does not claim authenticated MFL success or recommend a purchase.

## Key blockers before choosing this as the live authority

1. **Data must be made real.** The existing [Rolling Insights client](../src/data/rolling-insights.ts) returns unnormalized payloads; [mapping evidence](../src/data/mapping-evidence.ts) deliberately does not claim an authenticated NFL mapper. The prospective low-cost alternative discussed in platform selection is not an implemented adapter. Verify canonical player/game IDs, schedule and bye coverage, every ratified point-bearing field, missing-versus-zero behavior, freshness, corrections, outages, quota and display rights against the chosen source. Do not buy a feed on the assumption that this is already connected.
2. **There is a draft-start trap.** `startDraft` currently checks the constitution and catalog size, but does not enforce initial scoring configuration. Once drafting has finished, `ScoreboardService.configure` permits only upcoming weeks with existing season scoring. An ungated draft can therefore activate a league whose current week cannot be introduced through the normal scoring interface. Enforce and test the complete pre-draft configuration gate.
3. **The weekly operating loop is incomplete.** Build a repeatable routine for schedule/mapping completeness, acquisition windows, previous-week disposition, lineups and transitions. Define intentionally empty slots, bye starters and cancelled-game scoring: currently an empty slot is unknown and cancelled/postponed stats do not finalize a matchup. Prevent incomplete or subsequently corrected scores from silently driving season results.
4. **“Win the league” needs an executable definition.** Implement and ratify standings, ties, playoff places/byes/seeding, bracket progression, correction deadlines and final champion/last-place determination. The current scoring service explicitly rejects weeks outside the ratified regular season; postponing this work does not make postseason hosting available.
5. **Operational proof is still required.** [League event dispatch](../src/league/dispatcher.ts) and [transactional wakeup tests](../tests/league-events.test.ts) exist, as do [clock supervision](../scripts/league-clock.ts) and backup/restore scripts. Require a full real-feed rehearsal, missed-deadline/worker-restart recovery, alert ownership, data-reconciliation drills and off-device recovery evidence before treating the league as unattended. This audit did not inspect their live deployment state.

## Remaining work categories for the comparison

- **Data integration and entitlement:** authenticated adapter, identity mappings, formula coverage, correction replay, latency/outage measurements and permitted public output.
- **Season product rules:** standings, playoffs, ties, intentional empty/bye/cancelled cases and accepted-trade or post-lock mapping exception procedures.
- **Weekly automation:** complete pre-draft checks, recurring acquisition periods, next-week preparation and safe transition/finalization.
- **Operations and human use:** owner/commissioner rehearsal on phones, failure alerts, supervised workers, reconciliation, backups and restoration.
- **Validation and continuing maintenance:** adversarial season scenarios, comparison against independent scores, vendor schema changes and later rule changes. Existing local tests reduce this work; they do not replace it.

No hour estimate is supported by this audit. Compare these concrete obligations with the authenticated hosted trial before committing funds or a season. If a host supplies and verifies these mechanics, keep that host as the single football ledger and retain Black4's models, wallets, collaboration, decision receipts and public projection around it. Do not run two competing live ownership/scoring ledgers.
