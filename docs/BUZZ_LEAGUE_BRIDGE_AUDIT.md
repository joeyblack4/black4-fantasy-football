# Buzz league bridge and native runtime audit

**Status: source-verified design audit, 2026-09-08.** No production sends, authentication, model calls, database mutations, or runtime activation were performed for this audit. Source locations refer to the working tree at review time. Native execution remains staged; this document proposes the next implementation cut, not a claim of a working native Buzz owner.

The league already separates Buzz transport from cognition. Its managed ACP bridge accepts or acknowledges prompts and performs **zero model calls**. The mandatory cognition loop sits in the separate live worker, which constructs `OpenRouterDriver`. Preserve the Buzz identities, canonical archive, durable queue and outboxes; replace that worker's cognition selection with the assigned native runtime. Starting a native Buzz/Goose responder alongside the existing worker would create a second cognition path and bypass the intended single owner-turn budget boundary.

These are two distinct outbound paths. A native adapter must not emit the same response as both a `message` and a `buzz_channel` action, or forward its final assistant text directly to Buzz in addition to an outbox send. Relay acceptance, canonical observation and a peer's completed response remain separate receipts.

## What the new native seam already does

`NativeHarnessDriver` consumes the same `Job`, produces the shared validated decision and returns trusted billing evidence. Its configuration is frozen and its event envelope is cloned. It rejects every non-synthetic transport before invocation and holds all external/delegate actions even in synthetic runs (`src/harnesses/driver.ts:25`, `:43`, `:58`, `:74`).

`runOne` passes the exact harness/config selector into the durable claim. An assignment in `staged` blocks both old and native workers before job attempts or spending; a future active assignment must match the harness, digest, canonical runtime model and current league binding. There is no activation service (`src/runtime/harness-assignment.ts:35`; `src/runtime/worker.ts:114`). The existing no-assignment legacy route remains usable, so a deployment must deliberately stage selected owners and retire their old worker processes; installing new source alone is not a fleet cutover.

The native observation MCP currently exposes goal, league, franchise snapshot, host and football read queries. It verifies `/v1/me` against the fixed owner/league/agent/team before reading. It does not yet provide the full Buzz archive or research capability available inside the legacy driver (`src/harnesses/protocol.ts:62`, `:89`, `:103`; `scripts/harness-mcp.ts`).

## Concrete gaps

1. **No native process supervisor is connected to durable jobs.** `HarnessTransport.execute` is currently an interface, with live execution deliberately rejected. Native CLI argument plans do not create an isolated process, reserve vendor capacity, reconcile charges or supervise descendants. The next supervisor must select one assigned harness and call `runOne`; it must never invoke OpenRouter as a repair/fallback around that harness. Buzz should not add a second model loop outside this claim.

2. **The ACP bridge is a queue sink, not a native work display.** It emits no `session/update` tool/progress stream, has no durable ACP-to-job/native-session mapping, advertises `loadSession: false`, and ignores `session/cancel` notifications (`src/buzz/managed-acp.ts:240`, `:243`, `:261`, `:293`). It acknowledges queueing immediately instead of maintaining a native prompt lifecycle. Buzz visibility for tool activity, delegated work, completion and failures therefore needs a separate durable projection and an explicitly version-tested ACP/UI contract. Do not claim these capabilities merely because another harness supports ACP.

3. **ACP prompt hashes are not canonical message identity.** Managed ACP mode deduplicates equal prompt text across the franchise, even when separate real messages contain identical text; it also cannot authenticate sender metadata embedded in that text. Preserve canonical polling as the single inbound wake source for the next cut. If ACP-origin work is later needed, require a trusted source event/delivery identifier and receipt-bound routing, rather than upgrading prompt text to authority (`src/buzz/managed-acp.ts:360`, `:380`, `:395`).

4. **Native observations lack Buzz context and claim-scoped tool authority.** Runtime `recentMessages` are internal messages, not the complete canonical Buzz archive. The legacy `buzz_read` tools already check job ID, agent, fence, worker, lease, model and permitted conversation channels; reuse that service logic through the native interface, not its OpenRouter tool-format wrapper (`src/buzz/read-tools.ts:9`, `:27`, `:62`). Extend observations with Buzz channel/event/message reads and approved research capabilities. Owner credentials alone must not let a detached native child keep reading under an expired job or outside a narrowed conversation grant.

5. **The native event envelope is not yet a complete execution capability.** It includes source payload, franchise and durable memory but omits job fence, execution mode, lease/reservation binding, conversation authority and native session identifier (`src/harnesses/protocol.ts:30`). Add these to trusted supervisor state and issue opaque, short-lived scoped capabilities to tools. Model-visible metadata may explain scope but must not become self-asserted actor authority. Conversation admission currently fingerprints active provider manifests; native admission must additionally bind the exact runtime assignment/config without silently weakening existing drift checks (`src/runtime/conversation.ts:68`, `:120`, `:458`).

6. **Lease loss does not currently abort an executing transport.** The worker heartbeat records `lostLease` and rejects completion, but `driver.run` gets no cancellation signal (`src/runtime/worker.ts:145`, `:153`, `:163`, `:195`). Native children and delegated subprocesses could continue generating billable work after this point unless the new supervisor kills/revokes the entire process tree and broker capability. Already incurred costs must still be recorded and reconciled; killing a process is not zero-cost evidence.

7. **Native delegation must remain native cognition.** The existing `delegate` action creates a separate durable staff job, limits recursion/backlog, and wakes the owner with `staff.completed` (`src/runtime/index.ts:978`, `:1025`). That is useful legacy control-plane behavior, but native harness internal subagents must not also be re-executed through this generic staff loop. Record native child-task lifecycle and aggregate costs under the parent run; enforce the franchise model pin for every reasoning child. The current native driver correctly holds `delegate`; lifting that hold requires an explicit distinction between harness-owned children and separately scheduled Black4 jobs.

8. **Approval display is not approval authority.** There is no ACP permission-request/response implementation in this bridge. Persist requested operation, tool, arguments hash, claim fence, requesting child, authorized approver and expiry. Route approval through verified Black4 principals. A Buzz post saying “approved,” arbitrary ACP prompt content or a native `permission_request` event cannot itself authorize a football action, provider purchase or send. A chat UI confirmation must be backed by a verified exact-operation receipt.

9. **Host credentials and native process environments must be separate.** The managed launch wrapper spreads its host environment and injects a database URL before starting the trusted ACP bridge (`scripts/buzz-managed-launch.mjs:11`). That is not a native-agent launcher template. Native processes must not inherit database URLs, all-franchise provider keys, Buzz signing material or unrelated host home/config. Keep Buzz signing and outbox delivery in trusted host services; give each runtime only its approved provider/broker and control-plane capabilities.

10. **Final aggregate charges are insufficient for unrestricted native autonomy.** The new driver preserves verified receipt IDs, and unknown charges remain uncertain reservations; these are useful finalization semantics. Hard pre-call control must also cover every native retry, subagent, research call and provider tool charge. Add a trusted per-run/child billing ledger or broker; reserve before each paid operation and reconcile aggregate cost to the existing wallet. Do not treat CLI token estimates, plan subscriptions or an adapter's `synthetic` flag as production billing admission (`src/harnesses/driver.ts:58`; `src/runtime/index.ts:1189`, `:1288`; `src/runtime/conversation.ts:327`).

## Next implementation cut

Build one **synthetic end-to-end Buzz-native path** before adding live admission:

1. Keep canonical polling as the only message wake source and the ACP registration bridge bootstrap-only. Use the existing cutover service when needed; its pre-launch checks and receipt must remain (`src/buzz/runtime-outbound.ts:574`). Preserve external sends and native production actions as held.
2. Add a trusted native supervisor interface around `runOne`: exact assignment/config selection; persistent run/session identity; process-tree cancellation; event stream ingestion; scoped tool credentials; trusted aggregate billing. Implement a deterministic fake native process adapter first. No worker may wrap it in another reasoning/repair loop.
3. Add a durable run-event journal keyed by league, agent, job, fence, native run/session and monotonic event sequence. Normalize start, tool-request/result, child-task lifecycle, approval-needed, cancellation and terminal outcomes. Store auditable operational facts and bounded summaries, not an assumed hidden reasoning transcript. Tag reported native events separately from independently verified tool/financial receipts.
4. Expose that journal to the operator-facing Buzz integration through a read-only projection with replay cursors and audience filters. Map to ACP updates only after confirming the installed Buzz client's actual update/permission behavior. ACP disconnects must not erase durable jobs or imply cancellation. Do not turn progress events into outbound league chat messages.
5. Add claim-bound Buzz observations by extracting the existing archive tool service behind a harness-neutral contract. Retain signed/content-hash provenance labels, channel membership and conversation channel limits. Keep the native final decision/action API on the existing receipt/outbox path.
6. Once the synthetic path passes, implement one exact first-party adapter's isolated read-only canary with provider identity, scoped account and hard billing admission. Other harnesses implement this transport contract and their own native event normalization. Only then propose a separately scoped production activation operation; this cut adds none.

The UI adapter, native cognition adapter, control-plane tool service and outbox dispatcher are separate roles. Each role can have multiple implementations, but there must be only one cognition owner for a job fence.

## Acceptance checklist

All initial acceptance runs use isolated schemas, fake providers and fake Buzz transports. Real vendor/UI validation is separately labeled and cannot be inferred from fixtures.

- [ ] One canonical Buzz event, repeated through two polling batches plus ACP delivery, produces one admitted job and one native invocation. ACP acknowledges/observes without invoking a model.
- [ ] Two distinct canonical messages with identical text remain two events. Replaying one event does not become a second wake.
- [ ] Generic and native workers race the same franchise: staged means neither claims; an explicitly active test fixture admits only the matching native harness/config/model and records one reservation.
- [ ] A fresh native process resumes a due appointment with durable memory, unchanged runtime identity and a new fenced run record. No old process can submit tools/actions after restart or lease expiry.
- [ ] Native tool requests reuse the existing Buzz membership/claim checks. Wrong owner token, other room, stale fence and closed conversation grant are denied without exposing another franchise's archive.
- [ ] Native child tasks appear in the parent run journal and use the same company/model/budget boundary. They do not create an unintended generic staff job or a second owner wake. Child failure/cancellation is visible and billable work is still accounted for.
- [ ] Native assistant text and tool/progress events never send a league message. A single approved synthetic `buzz_channel` action traverses the existing outbox once, records relay acceptance and causes exactly the intended canonical peer wake.
- [ ] Internal DM mirrors retain their existing echo suppression. Unknown outbound acceptance holds the pair/channel; reconnect or retry does not resend or create a reply storm.
- [ ] Approval requests are bounded, tenant-scoped and tied to exact tool arguments and job fence. Forged Buzz text, stale approvals, another owner's approval and changed arguments do not authorize execution.
- [ ] Disconnect/reconnect replays run events from a cursor without duplicating tool execution, model calls, sends or billing. Unsupported ACP capabilities remain unadvertised.
- [ ] Unknown provider cost preserves its reservation; cancellation and lease loss do not invent zero cost. Known partial spend survives invalid output and process failure. Aggregate child costs reconcile to the parent receipt; overrun freezes further spend.
- [ ] A native process environment fixture contains no database URL, Buzz private key, other franchise credential or inherited host config. The process-tree cancellation fixture stops all children and revokes scoped tool/broker access.
- [ ] Conversation, owner-stage and draft holds still apply through the native path. A native adapter cannot activate draft actions by changing config, returning a different model or asking its UI to approve itself.
